# Бренд-менеджер — офлайн PWA

Сайт-приложение для управления запуском бренда на маркетплейсе: чек-лист, карта
процессов, еженедельная аналитика по WB/Ozon/Я.Маркет и калькулятор юнит-экономики.
Работает офлайн (после первого открытия) и синхронизируется между устройствами
через GitHub.

## Два репозитория — зачем

GitHub Pages на бесплатном тарифе публикует сайты только из **публичных**
репозиториев. Поэтому код разложен на два репозитория:

- **`brand-manager-hub`** (этот, публичный) — только код сайта: разметка,
  общие формулировки чек-листа, интерфейс. Никаких ваших цифр в нём нет.
- **[`brand-manager-data`](https://github.com/alenasivakovan-art/brand-manager-data)**
  (приватный) — файл `state.json` с вашими реальными данными (прогресс
  чек-листа, аналитика по маркетплейсам, юнит-экономика). Приватный репозиторий
  GitHub отдаёт содержимое только по действительному токену — без него запрос
  к API получает `404`, то есть данные защищены независимо от того, публичная
  ли ссылка на сам сайт.

## Первая настройка синхронизации

1. Откройте сайт → вкладка **Настройки** (логин и репозиторий для данных уже
   подставлены по умолчанию — `alenasivakovan-art` / `brand-manager-data`).
2. На github.com: **Settings → Developer settings → Fine-grained tokens →
   Generate new token**.
   - Repository access → Only select repositories → `brand-manager-data`
     (не `brand-manager-hub` — токен не должен уметь писать в код сайта)
   - Permissions → Repository permissions → **Contents: Read and write**
   - Создайте токен и скопируйте его (он показывается один раз)
3. Вставьте токен в приложении (поле «Personal access token»). Сохраните.
4. Повторите шаг 2–3 на каждом устройстве, с которого будете пользоваться
   приложением (телефон, ноутбук и т.д.) — токен хранится только в браузере
   этого устройства и нигде больше.

## Установка как приложение

- **Телефон (Android/iOS)**: откройте сайт в браузере → меню → «Добавить на
  главный экран» / «На экран Домой».
- **Компьютер (Chrome/Edge)**: иконка установки в адресной строке.

После установки приложение открывается отдельным окном без адресной строки и
продолжает работать без интернета — изменения синхронизируются, как только
связь появится снова.

## Структура

- `docs/` — сам сайт (публикуется через GitHub Pages из этого репозитория)
- `build/` — скрипт, которым исходный чек-лист (Markdown) был превращён в
  `docs/data.js`; нужен только при переносе туда новой версии документа
- `brand-manager-data` (отдельный приватный репозиторий) — файл `state.json` с
  вашими данными, пишется приложением через GitHub API, к этому репозиторию
  отношения не имеет
- Локальные копии PDF/Word/Excel остаются в папке «бренд» на компьютере — ни в
  один из репозиториев не входят

## Известные ограничения

- Автоматический еженедельный дайджест рынка (по воскресеньям) — это
  запланированная задача внутри Claude, статический сайт не может сам ходить в
  интернет по расписанию. Смотрите его в артефакте на claude.ai (ссылка на
  вкладке «Документы»).
- Синхронизация — «последняя запись побеждает»: если вы редактировали с двух
  устройств офлайн одновременно, при синхронизации сохранится более новая по
  времени версия целиком, а не по отдельным пунктам.
